# 案例11：补丁式修复失效 → 三层拦截系统（2026-05-13）

> 来源：`2026-05-13.md` 工作日志（一手记录）

**背景：** "先问再做"类错误在 9 个案例中反复出现（7/9），每次的修复方式都是"再加一条规则"。

## 第1层·事实

1. 累计已加 7 条规则（工作流硬性规则、方案B+ 声明机制等），**执行率并未提高**
2. 典型案例9 的流程违规记录：04-10 建规则 → 04-27 xwlb 任务违反 → 05-04 公众号任务仍违反（同一条规则 3 次违反）
3. 05-13 停止加规则，改为**重设计防护结构**：借鉴清华姚班 ABA 论文（陌生场景先问再动）、AI Agent Guardrails（代码强制而非 prompt 提醒）、航空检查清单（外部化记忆/逐项确认）
4. 产出「确认优先 — 三层拦截系统」：第1层场景识别（6信号）→ 第2层强制确认清单（5项阻塞式）→ 第3层事后审计
5. 实现位置：SOUL.md（**不是** MEMORY.md），嵌入任务执行工作流最前端

## 第2层·原因

### 补丁式修复的路径依赖
- 每次出错 → 复盘 → 加一条规则 → 下次仍出错。循环了 7 次才被识别为"手段无效"
- 根因：**prompt 规则可被跳过，无阻塞机制**。规则写在上下文里，是否被调用取决于执行时的注意力

### 修错了层
- 问题表现为"我忘了规则"，被误诊为"记忆力/自觉性问题"，于是修复方式是"再提醒一次"
- 实际是**结构问题**：没有把规则变成动作链上不可跳过的节点

## 第3层·底层模型

> **防护的位置决定防护的有效性。** 写在记忆里 = 可跳过；写在流程结构里 = 阻塞点。同一个规则，位置不同，效力差一个数量级。

> **反复用无效手段这是最贵的错误。** 7 次尝试的成本远高于第 2 次就质疑手段本身。判定标准：同一手段用 2 次无效，第 3 次必须换手段而非换措辞。

> 与已有复盘的关系：这是「行动优先 vs 确认优先」的**元层面**版本——不只是做事时行动优先，连**修复方式**也是"先加规则再说"，而非"先分析为什么加规则没用"。

## 第4层·能力

1. **手段有效性判断**：缺少"这个手段已经用过 N 次、有效吗"的计数意识
2. **把价值观转译为检查点**：从"要认真确认"到"6个机械信号 + 5项清单"的转译能力
3. **修改位置的选择**：改 SOUL.md（随人格注入、更靠前）而非 MEMORY.md

## 第5层·基本功

**对"加规则"的迷信：**
- 加规则给人"已经处理了"的完成感，但完成感 ≠ 有效性
- **加规则的成本低，所以被当成默认手段**——这正是它危险的地方
- 判断标准应是"同类错误下次还会发生吗"，而不是"我这次有产出吗"

## 下次要坚持的

1. **同一手段第 2 次无效即换手段**（不论措辞怎么改）——先问"为什么这个手段不生效"
2. **不确定场景的防护必须做成结构化阻塞点**：场景识别 → 强制确认清单 → 事后审计，每层独立，不依赖记忆
3. **规则改 SOUL.md 而非 MEMORY.md**——SOUL 是人格注入，位置更靠前
4. **完成判据挂可观测证据**：用户确认 / 工具返回码 / 文件校验通过，禁止用"应该好了"结案
