# 案例1：抖音视频转文字 L2 追问深化版（2026-04-15 初版，2026-05-05 追问更新）

**任务：** 给一个抖音链接，把视频内容转成文字，写入飞书多维表格。总耗时3.5小时，有效工作1.5小时，试错浪费2小时（57%）。

## 第1层·事实

- 5个弯路：yt-dlp下载到预览视频（40min）、Edge Cookie DPAPI失败（30min）、ffmpeg安装绕路（20min）、飞书API用错endpoint（20min）、Cookie提取脚本权限问题（10min）
- 成功路径7步，实际执行12步，多走5步冤枉路

## 第2层·原因

每个弯路的表面原因不同（工具不支持、加密变了、没包管理器、API记错了），但追问到第3层共性浮现——每次都是"先动手再确认"，用试错替代预判。yt-dlp没搜最新反馈就用、ffmpeg没检查环境就试winget、飞书API没查文档就凭印象调。

### 追问5：飞书所有者转移为什么用错API？

- 用了 `/permissions/{token}/transfer`（凭印象）
- 正确是 `/permissions/{token}/members/transfer_owner`
- 根因：**凭印象调API，没有先查文档**

这不是"记错了"这么简单——记错是结果，不查文档是原因。在不确定环境中（飞书API不是高频操作），凭印象行动就是行动优先策略的典型表现。20min浪费的链路：凭印象调错API → 返回权限不足 → 以为需要开通通讯录权限 → 开通后仍失败 → 才去查文档 → 发现endpoint本身就不对。

**追问结论：** API endpoint不是靠记忆的，是靠查文档的。对低频API，"确认优先"不是建议而是必须——1分钟查文档可以避免20分钟盲试。

## 第3层·底层模型

> **「行动优先」vs「确认优先」**：在确定环境中行动优先是高效的；在不确定环境中（新目标、外部依赖、环境未知），确认优先才是高效的。这次任务的每个弯路，都是把"确定环境"的策略用在了"不确定环境"上。
>
> 这个模型在之前3次任务中反复出现：地图标注（先模糊匹配后精确匹配）、服务器选型（先推最贵后降级）、飞书Cookie（先标准方法后绕路）——**三次任务，同一个底层问题。**

## 第4层·能力

缺失「环境预评估能力」——在动手前花3-5分钟系统性确认关键不确定项。具体三个子能力：
1. 环境探查：确认运行环境约束和可用资源
2. 工具可靠性验证：确认将使用的工具在当前目标上的可用性
3. 依赖链分析：梳理完整依赖链，标记高风险节点

## 第5层·基本功

不是不知道应该确认，而是行动惯性太强——拿到任务后第一反应是"开始做"而不是"先想清楚"。这是思维习惯问题，不是知识问题。

> **基本功：拿到任务后，强制停顿，问自己"我有哪几个关键信息还没确认？"**

## 下次要坚持的：行动前确认清单（3分钟）

1. 目标环境有什么限制？（反爬、加密、权限、包管理器）
2. 我选的工具在当前目标上还work吗？（最近有没有变化？）
3. 完整链路有哪些依赖？哪些是高风险节点？
4. 有没有5分钟能验证的关键假设？
5. **API endpoint是否已查文档确认？** — 不凭印象调低频API，1分钟查文档避免20分钟盲试（追问5新增）

**ROI验证：** 3分钟确认可省2小时。ROI = 40:1。
