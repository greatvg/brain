## 飞书文档内容修复 — lark-cli --markdown 参数误用

### 问题发现
荣总发现863篇飞书文档全部是垃圾——内容只有本地文件路径（如 `C:\Users\Admin\WorkBuddy\20260409211929\wechat-to-feishu\tmp\tmp_新韭菜八项注意.md`），没有文章正文。

### 根本原因
**lark-cli `--markdown` 参数接收的是 Markdown 内容字符串，不是文件路径。** 支持 `@file`（相对路径）和 `-`（stdin）两种文件输入方式。

原 batch_feishu.py 的逻辑：
1. 写 markdown 到临时文件 ✓
2. 把**文件路径**作为 `--markdown` 参数传入 ✗
3. lark-cli 把路径字符串当文档内容 → 863篇文档全是文件路径

### 验证过程
1. `docs +fetch --doc FHtzdadxGocI7SxWI71cBjTanyc` → 确认内容是文件路径
2. `docs +create --help` → 发现 `--markdown string  Markdown content (Lark-flavored) (supports @file, - for stdin)`
3. 测试 `@file` 语法 → 报错"must be a relative path within the current directory"
4. 测试 stdin 管道（`type file | lark-cli docs +create --markdown -`）→ 成功，内容正确
5. 测试 `docs +update --doc TOKEN --mode overwrite --markdown -`（stdin）→ 成功修复

### 修复方案
- 新脚本 `fix_feishu_docs.py`：用 Python `subprocess.Popen` + `stdin=PIPE` 直接管道传内容
- 对863篇已有文档：`docs +update --mode overwrite --markdown -`
- 对39篇之前失败的文档：`docs +create --title TITLE --markdown -`
- 断点续传：`fix_progress.json`

### 关键教训
**lark-cli --markdown 的三种用法**：
1. `--markdown "content string"` — 直接传内容（PowerShell引号处理麻烦）
2. `--markdown @./file.md` — 读相对路径文件（必须在当前目录下）
3. `--markdown -` — 从 stdin 读取（最可靠，用 subprocess.Popen 管道）

**教训：CLI参数的语义不能想当然，必须看 --help。** `--markdown` 看起来像"指定markdown文件"，实际是"传入markdown内容"。没看help直接用，导致863篇垃圾输出。
