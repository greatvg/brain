# 沉淀架构设计 v1.0

> 事实基础：2026-09-16 本机实测。C 盘剩 15.5 GB（93.9% 已用），E 盘剩 239.7 GB。
> 荣总四项裁决（2026-09-16）：**真源放 E 盘；清掉 memery；云端通道用 Git 私有仓库；明文密钥改成环境变量。**

---

## 0. 先定义需求，再选方案

**案例 6 教训（技术最优 ≠ 需求最优）**：如果直接比较"哪个方案技术最完整"，会得出"全量自建 Git+对象存储"，但对本场景是错的。先定需求：

| 维度 | 内容 |
|---|---|
| 谁 | 荣总一人，多机场景（至少会换电脑） |
| 场景 1 | 换电脑后，AI 还能认得我、项目还能续上 |
| 场景 2 | C 盘随时会满（现剩 16.7 GB），运行时数据必须搬 |
| 场景 3 | 沉淀散落 6 处，没有"唯一真源"，已产生过规则自相矛盾 |
| 硬约束 | 配置目录含明文密钥（§4），**禁止整体上云** |
| 不强求 | 多人协作、复杂版本分支、私有部署 |

**需求收敛成一句话**：一个**人能找到、AI 能直接读写、换机能带走**的真源目录；运行时垃圾另放，不上云。

## 1. 先把"有几个区"讲清楚（实测）

| # | 区 | 物理位置 | 内容 | 谁写 | 换机影响 | 体积 |
|---|---|---|---|---|---|---|
| 1 | **云端记忆摘要** | 腾讯服务器 → 缓存到 `~/.workbuddy/memory/<uid>_memory.md` | 你的长期画像（工作/个人/近期动态） | 服务器自动，版本已到 **239** | ✅ 跟账号走 | 49 KB |
| 2 | **僵尸记忆区** | `~/.workbuddy/memery/<uid>_memery.md` | 旧版画像，**停在 2026-04-29（版本 76）** | 已停更 | ✅ 跟账号走 | 8.8 KB |
| 3 | **跨项目规则/身份** | `~/.workbuddy/`：SOUL.md / IDENTITY.md / USER.md / MEMORY.md / AGENTS.md / 认知盲区*.md | 人格 + 做事方法 + 跨项目偏好 | 森林（需你确认） | ❌ **纯本地，换机就丢** | 87 KB |
| 4 | **项目级记忆** | `<工作区>/.workbuddy/memory/`：MEMORY.md + 每日日志 + cases/ + 复盘模板.md | 项目经验、案例库 | 森林自动写 | ❌ 纯本地 | 小 |

**关键澄清（你的两个误解）：**

- **`memory` 与 `memery` 是两个不同的东西，不是同一个的两种拼法。** `memory` 是**现在生效**的云端画像（v239，今天还在更新）；`memery` 是**旧版记忆系统的遗留**（v76，停在 4 月 29 日，目录名本身就是产品里的拼写错误）。后者内容是过期的（还写着"腾讯产品经理""滚轴钟修复"），**建议清理**，否则哪天被误启用会污染上下文。
- **WorkBuddy 的"工作区"是个临时沙箱目录**，官方 FAQ 明说升级/隔天重启后原工作区文件夹可能消失。所以**任何要长期保留的东西都不能只放在工作区里** —— 这是第 4 区、第 5 区现在最大的风险。

## 2. 本地 / 云端怎么分工（三条判据）

按顺序问，任一命中即定：

1. **换电脑后还需不需要它？** 需要 → 必须上云或放非系统盘 + 同步。
2. **含不含密钥/隐私？** 含 → **禁止上云**，且不进任何同步目录。
3. **丢了能不能再生？** 能再生（缓存/日志/运行时）→ 不上云，只搬出 C 盘。

| 类别 | 上云 | 搬出 C 盘 | 说明 |
|---|---|---|---|
| 规则/身份文件（第 3 区） | ✅ 必须 | ✅ | 这是"我还认得你"的唯一载体 |
| 项目记忆 + 案例库（第 4 区） | ✅ 必须 | ✅ | 经验的复利在这里 |
| Skill 库（第 5 区） | ✅ 建议 | ✅ | 86 MB，换机重装很痛 |
| 项目资产（剧本/调研/数据） | ✅ 必须 | — | 已在 D/E 盘 |
| 云端画像（第 1 区） | 已在云 | — | 无需操作 |
| 僵尸区（第 2 区） | ❌ | — | 建议清理 |
| 运行时（第 6 区） | ❌ | ✅ 优先 | 3.27 GB，可再生 |
| **`settings.json` / `models.json`** | ❌ **绝对禁止** | — | 含明文密钥，见 §4 |

## 3. 推荐架构（三层，不是三选一）

**核心判断：Obsidian、IMA、资料库不在同一个维度上，所以不是三选一。**

- **Obsidian = 本地 markdown 文件夹的阅读器**，本身不是云。WorkBuddy **可以直连**（它就是普通文件夹，直接读写即可，不需要任何插件）。你"WorkBuddy 不能直连 Obsidian"的印象是错的。
- **IMA / 资料库 = 云端 SaaS**，是服务，不是文件系统。

因此正确做法是**分层**：

```
        ┌───────────── 真源层（唯一）─────────────┐
        │  一个本地目录  E:\brain\                │
        │  ・人读：Obsidian 直接打开这个目录       │
        │  ・AI 读：森林直接读写（无需插件）       │
        │  ・换机：私有 Git 仓库 push/pull         │
        │  ・历史：Git 提供回滚                    │
        └──────────────────────────────────────┘
                 │              │
        ┌────────┘              └────────┐
        ▼                                ▼
   IMA（检索层，只读派生）      资料库（交付层，只读派生）
   把要"语义搜索"的喂进去        要给团队看/在线打开的放这儿
   方法论、调研结论              汇报页、数据表、看板
```

**铁律：真源只有一个（`E:\brain\`），IMA 与资料库都是从真源**单向派生**出来的，绝不回写** —— 否则又是"一规多副本"，正是我们今天刚根除的病。

### 各方案优缺点对照

| 方案 | 本质 | 换机 | AI 直读写 | 目录结构 | 版本历史 | 主要缺点 |
|---|---|---|---|---|---|---|
| **本地目录 + Obsidian** | 文件夹 + 阅读器 | 需配同步 | ✅ 直接 | ✅ 最强 | ❌ | 单机，必须配同步通道 |
| **+ Git 私有仓库** | 加一层版本与云 | ✅ clone | ✅ | ✅ | ✅ 最强 | 需懂基本 git；大文件不适合 |
| IMA | 云端知识库 | ✅ | ✅ 有 skill | ⚠️ 弱（库/笔记） | ❌ | 不适合当"资产目录"；视频/YouTube 不支持 |
| 资料库 | 云端内容库 | ✅ | ✅ 有 skill | ⚠️ 节点树非文件系统 | ⚠️ 有限 | 批量搬迁麻烦；平台锁定 |
| 网盘同步文件夹（坚果云等） | 文件夹镜像 | ✅ | ✅ | ✅ | ❌ 弱 | 冲突难解；无历史 |
| 移动硬盘 | 冷备 | ⚠️ 手动 | ✅ | ✅ | ❌ | 会忘、会不同步 |

**推荐组合：本地目录（Obsidian 读）+ Git 私有仓库（换机与历史）**，IMA 与资料库降为派生层。

**关于 Git 的诚实提醒**：本机直连 GitHub 走代理，而代理今天已出现"假活"（TCP 通、请求全超时），push 会不稳。若不想折腾，**降级方案 = 云盘同步文件夹**（零学习成本，但没有版本历史）。这个选择权在你。

## 4. 安全红线与密钥处理结果（2026-09-16 执行完毕）

扫描结果 —— 这两个文件曾含明文密钥，一旦上云等于泄露：

| 文件 | 内容 | 处理结果 |
|---|---|---|
| `~/.workbuddy/settings.json` | 飞书 `appSecret`（明文 2 次）+ 微信 `botToken` | ❌ **程序不支持环境变量展开**（源码取证：`resolveEnvVariables` 全程序 6 处，4 处调用点全部在 models.json 解析路径，零处碰 settings.json）→ 保持明文，靠 **gitignore 白名单 + 禁止上云** 防护；建议未来轮换密钥 |
| `~/.workbuddy/models.json` | 3 个 `apiKey`（OpenAI 格式 / Ark / 第三方） | ✅ **已改为 `${WB_KEY_*}` 环境变量引用**——先写用户级环境变量（注册表读回 md5 逐项验证），再改文件；`models.json` 明文已清零 |

**models.json 环境变量支持的源码铁证**（app.asar 内 `resolveModelEnvVariables`）：程序启动时对 `apiKey` / `url` 字段做 `${VAR}` 展开；**取不到环境变量时原样返回字面量**——所以顺序必须"先设变量、验证、再改文件"，本次已按此顺序执行。

**铁律**：
1. `~/.workbuddy/` **整体禁止纳入任何同步目录**。
2. Git 仓库白名单已在 `E:\brain\.gitignore` 落地并实测（`git add -A` + check-ignore 双向验证：**零泄露、零漏放**）。
3. 若未来轮换密钥：飞书 appSecret 在飞书开放平台重置；模型 apiKey 在各平台控制台重置。

## 5. C 盘减负（最紧急）与两个关键发现

现状：C 盘剩 **15.5 GB（93.9%）**。实测大头：logs 1.9 GB / binaries 3.9 GB（10 万文件）/ traces 1.13 GB / **历史工作区 `C:\Users\Admin\WorkBuddy\` 3.1 GB（60+ 个目录，5 月堆到现在）**，合计约 9.5 GB+ 可争取。

### 发现 A：跨盘搬迁只有"目录联接"一条路（实测）

`mklink`（文件符号链接）与 `mklink /D`（目录符号链接）均**权限不足**；仅 `mklink /J`（目录联接）可用。⇒ 散文件无法单独搬盘，只能"整目录搬 + 联接回挂"。

### 发现 B：存在官方环境变量开关 `WORKBUDDY_CONFIG_DIR`（源码取证，可能比 junction 更优雅）

app.asar 源码多处（>8 处）出现同款解析：

```js
configDir = process.env.WORKBUDDY_CONFIG_DIR?.trim()
         || process.env.CODEBUDDY_CONFIG_DIR?.trim()
         || path.join(os.homedir(), ".workbuddy")   // ← 默认基于用户主目录，与安装盘无关
```

另有 `WORKBUDDY_DATA_DIR`、`WORKBUDDY_DATA_FOLDER_NAME`（只能改主目录下的文件夹名，专享版为 `.aimea`）、`WORKBUDDY_USER_DATA_DIR`。

**含义**：设置用户级环境变量 `WORKBUDDY_CONFIG_DIR=E:\wb-data` 后重启 WorkBuddy，整个 `~/.workbuddy` 可能整体重定向到 E 盘——**一步到位约 9 GB**，比逐目录 junction 干净。

**诚实边界（未验证）**：① 源码注释说"Desktop 主进程 configureElectronApp 已按 dataFolderName 写入"该变量，主进程是否尊重外部预设值**未实测**；② 工作区目录 `C:\Users\Admin\WorkBuddy\` 是否受同一变量控制**未知**；③ 本会话不能重启 WorkBuddy 验证。

### 待裁决：C 盘减负走哪条路

| 方案 | 做法 | 优点 | 风险 | 回滚 |
|---|---|---|---|---|
| **E1 环境变量重定向（推荐先试点）** | 复制 `~/.workbuddy` → `E:\wb-data`；设 `WORKBUDDY_CONFIG_DIR`；重启 WorkBuddy 验证 | 若生效一步到位 | 若程序不认 env 或部分认，出现新旧目录分裂；需重启验证 | 删环境变量即可，数据原件未动 |
| **E2 逐目录 junction（已验证可行）** | logs / traces / binaries / cache 整目录搬 E 盘 + `mklink /J` 回挂 | 不依赖重启验证；已有成功先例（工作区记忆区就是这么迁的） | 分批操作、句柄占用风险 | 删联接搬回 |
| **E0 纯垃圾直接清（两者都可叠加）** | logs 1.9 G + traces 1.1 G + cache/blobs 0.4 G 直接删（可再生） | 立释放 ~3.4 GB | 无 | 无需回滚 |

**另需荣总确认**：60+ 个历史工作区目录（3.1 GB）内有各项目早期记忆/会话记录，删除前须先扫描是否有未迁出的独特内容——按"个人文件红线"，扫描报告先出，删除另行确认。

## 6. 目录设计（真源目录）

设计原则：① 编号前缀控制排序（人读友好 + Obsidian 侧边栏不乱）② 项目内部自含 README，入口唯一 ③ 知识与项目分离（知识跨项目复用）④ 运行时数据永不进来

```
E:\brain\                       ← 唯一真源（Git 私有仓库；Obsidian 打开此目录）
├── .gitignore                  ← 排除密钥/大文件
├── 00-身份与规则\
│   ├── SOUL.md                 ← 做事方法（唯一归属）
│   ├── IDENTITY.md  USER.md
│   ├── MEMORY.md               ← 跨项目偏好
│   └── 认知盲区双轨框架.md  认知盲区证据台账.md
├── 10-项目\
│   ├── 剧本-红孩儿\            ← 项目内自带 README.md 作入口
│   ├── 产业侦探\ 海关数据\
│   ├── 银发守护\ 尹子老师\ 古文断句\
│   └── 供应链侦探-YouTube\
├── 20-知识\
│   ├── 复盘案例\               ← 承接现 cases\（案例1-13）
│   ├── 方法论\                 ← 剧本五维/认知触发/阻力对抗/双三角
│   └── 调研存档\
├── 30-素材\                    ← 大文件，Git 排除或 LFS（可另走网盘）
├── 40-模板\                    ← 复盘模板等
└── 90-归档\                    ← 过期项目与旧版本
```

**与现状的映射**：

| 现在在哪 | 应该去哪 |
|---|---|
| `~/.workbuddy/{SOUL,IDENTITY,USER,MEMORY,AGENTS}.md` | `00-身份与规则\` |
| `<工作区>/.workbuddy/memory/MEMORY.md` + 每日日志 | `10-项目\<项目>\` 或 `20-知识\` |
| `<工作区>/.workbuddy/memory/cases/` | `20-知识\复盘案例\` |
| `<工作区>/.workbuddy/memory/复盘模板.md` | `40-模板\` |
| `~/.workbuddy/skills/` | 建议留在 `~/.workbuddy/skills/`（程序要读），用 Git 单独跟踪 |
| `D:\海关数据` `D:\产业侦探` `E:\silver-guard` `E:\专家辩论` | `10-项目\<同名>\` |
| `E:\douyin_downloads`（1 GB） | 不建议进 Git，留在原地或走网盘 |

## 7. 换机 SOP（确认方案后执行）

1. 新机装 WorkBuddy，登录同一账号 → 云端画像自动恢复（第 1 区）
2. 装 Git，`git clone <私有仓库> E:\brain`
3. 把 `E:\brain\00-身份与规则\*.md` 复制（或 junction）到 `~/.workbuddy\`
4. 把 `E:\brain\20-知识\`、`10-项目\` 原样使用；Obsidian 打开 `E:\brain`
5. 按需从资料库/IMA 取派生内容
6. **不复制** `settings.json` / `models.json`，在新机重新配置（或从环境变量读）
